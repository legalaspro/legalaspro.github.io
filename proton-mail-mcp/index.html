MCP server for Proton Mail Bridge · v1.30.0

Proton Mail for your AI agent. Nothing moves or sends until you approve.

mcp-proton-mail is an open-source MCP server that runs on your own computer, next to Proton Mail Bridge. Your agent can search, read and draft. To move, delete or send mail it needs a single-use token tied to the exact messages you approved.

Install in one line

uvx mcp-proton-mail setup

Run it in your own terminal. It prints its plan and changes nothing until you say yes. Then it checks or installs Bridge, keeps the Bridge password in your system’s credential store, starts the local service and checks that it can read your inbox.

Needs a paid Proton plan (Bridge requires one) and uv. Linux and macOS; Windows support is new, so read docs/windows.md first. Add --client <name> to connect your app as well.

Connect: Claude Desktop · Claude Code · ChatGPT · Codex · Gemini CLI · Cursor · Grok Bot

Installing it for someone? Follow llms-install.md. Summary for agents: llms.txt.

Setup

Connect your client

Setup writes the config for seven clients. Each entry starts proton-mail-mcp connect, a local relay that reads the token itself, so your client’s config holds no password and no token. ChatGPT is the one exception.

ChatGPT (Mac app)

New install

Already set up

uvx mcp-proton-mail configure-client --client chatgpt

Entry it writes

[mcp_servers.proton-mail]
url = "http://127.0.0.1:8765/mcp"
http_headers = { Authorization = "Bearer <token>" }
tool_timeout_sec = 150

In ~/.codex/config.toml, shared with Codex. ChatGPT connects over HTTP, so this entry holds the bearer token, and setup writes the file owner-only. Writing it by hand? uvx mcp-proton-mail show-token --copy puts the token on your clipboard without showing it. ChatGPT guide

Then

Add the tool_timeout_sec = 150 line by hand, then quit the app completely and open it again. ChatGPT on the web cannot reach your computer.

How approval works

Your approval is tied to the exact messages.

Tool descriptions ask the agent to wait for you, but text cannot enforce that, so the server does not rely on it. A change goes through only with a token the server issued for one exact preview, and only after you accepted that preview in your client.

Where the check is weaker

  • A client that answers forms by itself defeats the form step.
  • On a client with no forms, you approve a send by typing OK in chat. The server cannot prove a person typed it. PROTON_MCP_SEND_TYPED_OK=0 turns that path off.
  • PROTON_MCP_CONFIRM_MUTATIONS=0 lets the token alone approve a change. It is on by default.

How approvals work, in full

  1. You ask

    “Put last month’s newsletters in the Trash.” The agent searches first. Searching and reading open folders read-only, so nothing is marked read.

  2. The server previews and issues a token

    preview_action returns the count, a few samples, the target and a single-use token. The token is bound by a SHA-256 hash to that action and those messages, lives only in memory and expires after 10 minutes by default.

  3. Your client asks you

    Before the token works, your client shows a form with the stored change, never the agent’s wording of it: Move 12 message(s) to "Trash".

    Decline it, or let it time out, and the token is retired.

  4. The server checks again, then acts

    It reads those messages again and refuses if anything differs. Then it makes the change and logs it. Moves, labels and read state can be undone once with undo_action.

Sending is off by default

With PROTON_MCP_ENABLE_SEND=1, there is one path, through Bridge on 127.0.0.1:

  1. create_draft
  2. →
  3. preview_send
  4. →
  5. your approval
  6. →
  7. send_draft

The send token covers the draft’s exact bytes and recipients and lasts 5 minutes by default. Edit the draft after the preview and the send refuses.

Local by design

It runs on your computer. Nothing is hosted.

The server runs under your login, beside Bridge, and listens only on 127.0.0.1. There is no account to create and no service in between.

  • Secrets in your credential store

    The Bridge password and the server’s bearer token live in Keychain, libsecret, pass or Windows Credential Manager.

  • No tool to empty Trash

    Nor to delete or rename a folder. Permanent deletion reaches only drafts you approved.

  • An audit log without content

    Every write call is logged, append-only, with no bodies, subjects, full addresses or tokens.

In the chat

Three views for clients that support MCP Apps

Your client draws them inside the conversation. They load nothing from the network and never hold an approval token. Clients without MCP Apps get the same results as text.

  • Thread view

    show_thread

    A read-only thread: headers, a cleaned-up body, and each attachment’s name, type and size. Nothing is marked read.

    Links don’t open on click. The view first shows the full address a link really goes to, and opens it only when you confirm.

  • Reply composer

    compose_reply

    A reply or a new message, filled in by the agent and edited by you. It saves an unsent draft in Drafts.

    It has no way to send, even with sending turned on.

  • Send review

    review_send

    The exact send preview of one saved draft, so you can read what would go out before you approve it.

    It exists only with sending on, and it issues no token.

sethbang’s may suit you if

you want sending ready out of the box, a Node.js toolchain, folder rename and delete, or inbox statistics, and you are happy to set credentials in your client’s config.

Questions

Before you connect

Is it official?

No. mcp-proton-mail is unofficial and is not affiliated with or endorsed by Proton AG. It is open source under the Apache-2.0 license.

Does my mail leave my computer?

The server and Bridge run on your computer, and the server listens only on 127.0.0.1. Bridge talks to Proton as it always does.

What your agent reads becomes part of its conversation and goes wherever its model runs. The local search index holds headers, not bodies.

Can the agent send mail without me?

Sending is off by default, and then there is no send tool at all. With sending on, each send needs a saved draft, a fresh preview and your approval in the client’s form.

On a client without forms you type OK in chat instead, which the server cannot verify. Set PROTON_MCP_SEND_TYPED_OK=0 to refuse that path. Sending mail

Do I need a paid Proton plan?

Yes. The server reaches your mail through Proton Mail Bridge, and Bridge needs a paid plan.

Does it run on Windows?

Native Windows support is new and has run only on GitHub’s Windows Server runners, not on Windows 10 or 11 with a real Proton account. Read docs/windows.md first, or use WSL2 and the Linux steps.

How do I undo a change, or uninstall?

Ask your agent to undo it: undo_action reverses a logged move, archive, trash, read-state, label or folder-rule change, once. Sending, draft deletion and unsubscribe cannot be undone.

To uninstall, look at the plan first, then run it:

uvx mcp-proton-mail uninstall --dry-run
uvx mcp-proton-mail uninstall

It keeps your stored credentials unless you add --remove-credentials, Bridge unless you add --remove-bridge, and each client’s proton-mail entry, which you remove yourself.
