MCP server for Proton Mail Bridge · v1.30.2

Proton Mail for your AI agent. Nothing moves or sends until you approve.

An open-source MCP server that runs on your computer, next to Proton Mail Bridge. Your agent can search, read and draft. To move, delete or send mail it needs a single-use token tied to the exact messages you approved; undo_action, when you ask, needs none.

Install in one line

uvx mcp-proton-mail setup

Run it in your own terminal. It shows its plan and changes nothing until you say yes, then sets up Bridge and the local service. --dry-run shows the plan and stops.

Add --client <name> to connect your app: claude-desktop, claude-code, chatgpt, codex, gemini, cursor or grok-bot.

Needs a paid Proton plan (for Bridge) and uv. Linux and macOS; Windows support is new.

Privacy and approval

The server runs under your login, beside Bridge, and listens only on 127.0.0.1. There is no account to create and no service in between.

  1. Your MCP client
  2. ↔ mcp-proton-mail127.0.0.1:8765
  3. ↔ Proton Mail Bridge
  4. ↔ Proton

Apart from saving drafts or attachments and undo_action, every change needs a preview, a single-use token tied to it, and your OK in your client’s form (reindex has none). The server then reads the messages again and refuses if anything differs. Moves, labels and read state can be undone once.

  1. preview_action
  2. → your approval
  3. → re-check, then act

Sending is off by default. With PROTON_MCP_ENABLE_SEND=1 there is one path, through Bridge on 127.0.0.1, and the send token covers the draft’s exact bytes and recipients:

  1. a saved draft
  2. → preview_send
  3. → your approval
  4. → send_draft
  • Passwords and tokens stay in Keychain, libsecret, pass or Windows Credential Manager, except the ChatGPT entry’s token.
  • No tool empties Trash or deletes a folder; permanent deletion reaches only drafts you approved.
  • The audit log records every write call, with no bodies, subjects, full addresses or tokens.
  • What does leave: mail your agent reads goes wherever its model runs.
Where it is weaker: auto-answering clients, a typed OK, the form off
  • A client that answers forms by itself defeats the form step.
  • On a client with no forms, you approve a send by typing OK in chat. The server cannot prove a person typed it. PROTON_MCP_SEND_TYPED_OK=0 turns that path off.
  • PROTON_MCP_CONFIRM_MUTATIONS=0 lets the token alone approve a change. It is on by default.

Before you connect

Is it official?

No. mcp-proton-mail is unofficial and is not affiliated with or endorsed by Proton AG. It is open source under the Apache-2.0 license.

Does my mail leave my computer?

The server and Bridge run on your computer, and the server listens only on 127.0.0.1. Bridge talks to Proton as it always does.

What your agent reads becomes part of its conversation and goes wherever its model runs. The local search index holds headers, not bodies.

Can the agent send mail without me?

Sending is off by default, and then there is no send tool at all. With sending on, each send needs a saved draft, a fresh preview and your approval in the client’s form. The send token lasts 5 minutes by default; edit the draft after the preview and the send refuses.

On a client without forms you type OK in chat instead, which the server cannot verify. Set PROTON_MCP_SEND_TYPED_OK=0 to refuse that path.

Sending mail
Do I need a paid Proton plan?

Yes. The server reaches your mail through Proton Mail Bridge, and Bridge needs a paid plan.

Does it run on Windows?

Native Windows support is new and has run only on GitHub’s Windows Server runners, not on Windows 10 or 11 with a real Proton account. Read the Windows notes first, or use WSL2 and the Linux steps.

docs/windows.md
Setup says the Bridge app is running

Setup runs Bridge as a background service. Quit the Proton Mail Bridge app first, or add --skip-bridge-service to keep the app running Bridge.

How do I undo a change, or uninstall?

Ask your agent to undo it: undo_action reverses a logged move, archive, trash, read-state or label change once, including the moves your folder rules made. Sending, draft deletion, unsubscribe, new folders and saved rules cannot be undone.

To uninstall, look at the plan first, then run it:

uvx mcp-proton-mail uninstall --dry-run
uvx mcp-proton-mail uninstall

It keeps your stored credentials unless you add --remove-credentials, Bridge unless you add --remove-bridge, and each client’s proton-mail entry, which you remove yourself.
